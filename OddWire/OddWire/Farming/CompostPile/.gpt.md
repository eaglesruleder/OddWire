# Doc — CompostPile

**Scope:** Feature  
**Domain:** OddWire.Farming  
**Status:** Active

---

## Summary

**Goal:** Converts organic inputs into compost over time via a tick-driven simulation of moisture, aeration, and temperature, through a two-stage pipeline — nutrition (or browns) decomposes into inoculum, then browns + inoculum convert to compost.

**Lifecycle:**
1. Craft from rot + drygrass, place block
2. Fill inputs — browns (drygrass), inoculum (rot/compost), nutrition (food items)
3. Maintain moisture — water manually or rely on rainfall if sky-exposed
4. Wait — simulation ticks every 12s, progressing moisture / aeration / temperature, then decomposition then composting
5. Harvest — break the block to dig it up (shovel hinted in interaction help, any tool works); drops compost, compostpile blocks, browns, inoculum
6. Turn — add any input to restore aeration; blocked neighbours accelerate aeration decay

**Rules:**
- Output room checked before any mutation (compost room, inoculum room)
- Decomposition (nutrition/browns → inoculum) costs material — consumes nutrition first, then browns; stalls when inoculum pool is full OR no material remains
- Composting (browns + inoculum → compost) stalls without ≥1 browns portion AND ≥1 inoculum portion AND compost room
- Composting hard-stalls when InoculumQty is below ConsumePerTransition (GetCompostFactor returns 0)
- Inoculum is a self-balancing pool — composting burns it (burn rate rises with the inoculum level via GetInoculumFactor01 → compost rate), decomposition refills it at the cost of nutrition/browns; the two settle at an equilibrium below ~50%. Nutrition raises that equilibrium (toward 100% inoculum factor): more production, but the higher factor lifts compost rate and thus burn — self-limiting, never runaway. A low inoculum reading is the steady state, not a fault.
- Nutrition is lossy — not recovered on harvest
- Inoculum input room is shared with compost — CompostQty imposes on inoculum add room
- Aeration decays faster when full, when neighbours block airflow, or with high-O2-demand nutrition
- Creative shape variants #1–#5 driven by TotalQty, stacked per 64

**State:**
`Stored: BrownsQty, NutritionStacks, InoculumQty, CompostQty, Moisture01, Temperature, Aeration01, AdjacentBlockCount, AdjacentBlockHeat, PrevTime* timestamps (Moisture/Temperature/Aeration/Decomposed/Processed) — Derived: CompostFactor, DecompositionFactor, Efficiency01, Insulation01, EnvTemp — Persisted: all stored state via per-field TreeAttribute keys`

## Implementation

### BlockCompostpile
Handles player interaction, neighbour notifications, and break/harvest routing.

```
OnLoaded()
  — build + cache 3 interaction-help entries from settings (via api.ResolveStack/ResolveStacks):
  — LClick + shovels = Turn; RClick + (Browns/Inoculum AddItemCodeRatios + compostpile) = Add; RClick + NutritionHelpCodes = Boost

GetPlacedBlockInteractionHelp()
  — append cached interactions to base help

OnBlockInteractStart()
  — require compostpile BE, require held stack
  — call be.TryAdd; reject if not accepted
  — server only: slot.TakeOut(accepted), slot.MarkDirty

OnHeldInteractStart()
  #region require non-shift compostpile target
  #region consume held input before default block placement
  #region fall through to base placement

OnNeighbourBlockChange()
  — flag be.NeighboursDirty on server

OnBlockBroken()
  #region require compostpile BE and server-side break authority
  — be.Harvest(dropQuantityMultiplier)
  — if be.CanHarvest(): return (pile still has contents, block stays)
  — base.OnBlockBroken (removes emptied block)
```

  #region move toward target (envTemp + GetInternalHeat + AdjacentBlockHeat x NeighbourHeatRate) via asymptotic coolingFactor


// #region Processing
// Intent: inoculum is a self-balancing pool. ProcessCompost burns it; burn rate rises with GetInoculumFactor01 (→ compost rate). ProcessDecomposition refills it at the cost of nutrition (then browns). They meet at an equilibrium <50%. Nutrition shifts the equilibrium up (more production, but higher inoc factor → higher compost rate → more burn) — never runaway. Browns feed both stages, so they are the master feedstock.

ProcessCompost()  — browns + inoculum -> compost
  #region guard timestamp; require browns AND inoculum portions AND compost room
  #region resolve transitions at rate = BaseCompostRatePerHour x GetCompostFactor, capped by capacity
  #region require transitions >= 1; else keep accruing
  #region consume browns + inoculum per transition, add compost
  #region advance PrevTimeProcessed by completed transition time

ProcessDecomposition()  — nutrition/browns -> inoculum (costs material)
  #region guard timestamp; require inoculum room AND material (nutrition + browns)
  #region baseTransitions = duration x BaseInoculumRatePerHour x GetDecompositionFactor x efficiency01
  // Intent: nutrition raises yield per unit time (factor-1 bonus); total capped by material then room
  #region transitions = Min(base + nutritionBonus, NutritionQty + BrownsQty, inoculumRoom)
  #region require transitions >= 1; else keep accruing
  #region cost nutrition first then browns; add inoculum
  #region advance _prevTimeDecomposed

### CompostpileSettings
Static tuning data only — no runtime logic.
Defines per-ingredient (Browns, Nutrition, Inoculum) quantities, conversion ratios, harvest yields, and per-food-category nutrition tuning (speed bonus, O2 demand, heat).
Regions: IngredientTuning, CompostRate, Moisture, Aeration, Temperature, Harvest, BlockInfo.
